# OceanBaseConnector for .NET

An experimental ADO.NET driver for OceanBase, with one provider, one protocol stack, and an authenticated mode state per connection for MySQL and Oracle compatibility modes. The optional DI package registers connections on all five targets and ordinary/keyed data sources on modern targets.

**The current version is `0.1.0`, independently versioned by this project.** Direct OceanBase 4.4.2.2 MySQL and Oracle profiles have real-database acceptance evidence; the full compatibility matrix remains incomplete and no release candidate has been published. See [verified scope and Java comparison](docs/compatibility.md). Local tests and a passing subset of real cases do not establish general production compatibility.

## Packages and target frameworks

| Package | Assets | Microsoft shared libraries |
| --- | --- | --- |
| `OceanBaseConnector` | netstandard2.0, netstandard2.1, net8.0, net9.0, net10.0 | Standard/net8 use 8.x; net9 uses 9.x; net10 uses 10.x. |
| `OceanBaseConnector.DependencyInjection` | netstandard2.0, netstandard2.1, net8.0, net9.0, net10.0 | Same minimum-version mapping; current core package version or newer, without an upper bound. |

Both packages share one version and packaging process. Root `Directory.Build.props` owns the project release version (`0.1.0`); it does not follow the official OceanBase .NET driver or Connector/J version. Root `Directory.Packages.props` centrally declares dependency minimum versions as inclusive, unbounded ranges (`[minimum,)`), and project PackageReferences omit Version metadata. The Microsoft dependency minimum is uniformly 8.0.0 for both Standard assets and net8, 9.0.0 for net9, and 10.0.0 for net10. Core uses logging abstractions and BouncyCastle.Cryptography >=2.7.0 for Ed25519; the Standard assets also use DiagnosticSource >=8.0.0, while modern assets use runtime diagnostic APIs. Core requires neither a DI container nor a logging backend. Standard assets retain basic ADO.NET and DI connection registration; `DbDataSource` and `DbBatch` are exposed only on the three modern targets. Standard2.1 also overrides the platform's asynchronous prepare, transaction, and resource-cleanup APIs.

Testing tools (`Microsoft.NET.Test.Sdk` >=18.11.0, xUnit >=2.9.3 and VS Runner >=4.0.1) belong to non-packable test projects and are absent from both product packages' runtime dependency groups. Open ranges do not automatically select or validate the newest release: restore normally selects the lowest applicable version, and consumers must test their chosen newer dependencies.

## Current capabilities and boundaries

Implemented with local regression coverage and selected real OceanBase 4.4.2.2 acceptance: sync/async connections with strict TLS, parameter validation, text and server-prepared execution, multi-result readers, exact numeric/date-time values, transactions, cancellation/timeouts, sequential field streams, forward-only paged cursors, initial catalog collections, MySQL database switching, sequential batches, data sources/DI/logging, and local tracing/metrics.

- Mode comes from the authenticated status, with `ExpectedMode` used only as a cross-check. MySQL mode and greetings that do not identify OceanBase require a read-only `ob_version()` confirmation before Open succeeds. This path currently admits only the verified OceanBase 4.4.2.2 version; native MySQL and other unverified versions fail. Wider version/OBProxy compatibility remains open.
- `Pooling=true` is rejected. Complete session reset and a version allowlist remain unverified; pooling is disabled by default.
- Binary Input parameters accept readable `Stream` values, inferred or explicitly `DbType.Binary`. Upload uses fixed 8 KiB chunks before execution: unanswered MySQL LONG_DATA, or Oracle PIECE_DATA with uppercase hexadecimal data and per-chunk OK. The driver does not buffer the entire source; Oracle uses one-byte lookahead to identify the final chunk. `Size`/`Precision`/`Scale` must be zero. The total execution budget is 64 MiB, including the actual execution request (SQL, extension header, and trailing fields for PrepareExecute); Oracle stream bytes count after hexadecimal encoding. Exceeding it fails. The caller exclusively owns, disposes, and repositions the source, read from its current position to EOF. One stream object may occupy only one binding position; repeated named expansion or shared parameter sources fail before sending. `Prepare` does not read the source, and repeated execution never rewinds it. Async upload uses source `ReadAsync` and the command's total budget; sources must cooperate with cancellation. Blocking sync reads or async reads ignoring tokens must return before interruption completes. Upload failure before EXECUTE destroys a contaminated session without sending business SQL; source failure before the first upload preserves a usable session. Oracle chunk ERR retains the server code and destroys the session because cleanup semantics remain unverified. After EXECUTE, no trustworthy terminal response means an unknown outcome; trusted server ERR retains its code and a usable session. The Oracle procedure/OUT PrepareExecute path independently prepares, uploads, then executes that statement ID. Each execution owns its ID; returned cursors may retain the parent statement. Existing version gates and `Use Oracle Prepare Execute=true` still apply. InputOutput streams are rejected; Output/ReturnValue ignores old Value and has no stream-output API. Text streams, client-prepare fallback, and array-binding stream combinations are not implemented. Wider server/OBProxy interoperability remains an acceptance gap.
- All five assets support per-command `UseCursorOffset=true` (default false) with positive `FetchSize` for Oracle >=2.2.5 extended Fetch. Readers remain forward-only and read-only; REF CURSOR uses its existing path. First execution shares strict `ob_version()` detection and physical-session caching with PrepareExecute; older or unrecognized versions are rejected. Each page consumes and validates its trailing OK before continuing or completing. NEXT/zero-offset requests and cumulative-position checks derive from protocol source and local fixtures only. Real-version/OBProxy compatibility is unverified; there is no scrolling API.
- Active local transactions on net8/net9/net10 expose `Save(name)`, `Rollback(name)`, and Async variants with `SupportsSavepoints=true`. MySQL also supports `Release(name)`/Async; Oracle rejects release. Names are 1–30 ASCII characters, starting with a letter, followed by letters/digits/underscores. Leading underscores (including ORM-generated `__EFSavePoint`), quoted names, and Unicode names are unsupported. Savepoints do not end transactions; business commands must remain bound to the original transaction. Reacquire previous LOBs, REF CURSORs, and complex descriptions/values after rollback to a savepoint. Standard assets do not add savepoint APIs. Basic savepoint rollback passed on the tested OceanBase 4.4.2.2 tenants; broader locking, DDL and duplicate/missing-name semantics remain unverified.
- Text commands and input parameters are supported by default; parameterized execution uses server prepare. Per-command `OceanBaseCommand.AllowClientSidePrepareFallback=true` explicitly enables fallback only when the first automatic-prepare response is a trusted, fully validated `1295/HY000`. One text SQL request then uses the original session, transaction, and timeout budget. Rejection is not cached; the next execution tries prepare again. Explicit `Prepare()`, FetchSize, Oracle PrepareExecute, execution errors, disconnects, and cancellation never downgrade or replay. Ambient `TransactionScope` is unsupported; explicit XA boundaries appear below. Locator LOBs require the options below.
- `Server` candidates are tried in declared order by default. `Load Balance=RoundRobin` (builder `LoadBalance`) rotates the preferred address on each explicit Open and tries the remaining candidates once after TCP connection failure. Modern data sources share rotation state; direct connections retain instance state across Close/Open, resetting it when the connection string or resolver changes. There is no global state, session/transaction/reader migration, execution-time reconnection, or SQL replay.
- All five assets expose `OceanBaseConnection.AddressResolver`; modern data sources fix it through `OceanBaseDataSourceBuilder.UseAddressResolver(...)`. Applications implement sync `IOceanBaseAddressResolver.Resolve(token)` and async `ResolveAsync(token)`. Each Open calls the matching method once for a trusted same-tenant list in existing Server syntax (at most 65536 characters/256 candidates; omitted ports inherit Port). Results replace candidates for that Open; empty/invalid/failed results never fall back to seeds or stale results. Configured Server remains required for pre-discovery diagnostics. Discovery, TCP, TLS, and authentication share one connection budget. Late async results are ignored after cancellation; sync implementations must cooperate, and async methods must return a Task promptly. Applications own resolver resources and concurrency safety; cancellation callbacks must return promptly without throwing. No built-in OCP/TNS protocol or role routing is provided. Every new session repeats TLS/authentication/mode initialization; real topology compatibility remains unverified.
- D09 provides immutable `OceanBaseXid(formatId, globalTransactionId, branchQualifier)`: signed Int32 format ID (`-1` reserved for NULLXID), 1–64-byte global ID, and 0–64-byte non-null branch qualifier. Inputs are copied; `GetGlobalTransactionId()`/`GetBranchQualifier()` return independent arrays. Equality/hash use all three fields; default string output omits identity. Constructing an XID starts or joins nothing. All five targets expose `connection.GetXaResource()` for MySQL/Oracle `Start/End/Prepare/Commit/Rollback/Recover`, sync and Task async, bound to the original physical session. Acquiring it dedicates the connection to XA until Close. Business commands require an Active branch and null Transaction; local transactions/database switching are rejected. Close does not implicitly complete branches. Public MySQL connections retain the A05 gate; local standard/OB20 fixtures supply explicit authenticated facts. Oracle DBMS_XA requires `Use Oracle Prepare Execute=true` and >=2.2.76; the first operation confirms autocommit off until Close. Identities are structurally bound, Prepare returns Prepared or ReadOnly, and non-success return codes use `OceanBaseException.XaErrorCode`, distinct from ERR `ServerErrorCode`. Recovery limits are 65536 MySQL/16383 Oracle branches. Basic prepare/recover/commit/rollback passed on the tested real OceanBase 4.4.2.2 tenants. External coordinators, crash recovery, OBProxy, and cross-machine acceptance remain open. See architecture D09 for recovery format/phase/error rules; do not bypass the resource API with raw transaction-control SQL.
- Client fallback supports basic input integers, finite floating point, exact decimals, binary, NULL, and ordinary Oracle strings. Date/time/time-zone, national, JSON, LOB, complex, and output values still require server prepare; NULL does not bypass special-type restrictions. Oracle strings retain VARCHAR2 semantics, double single quotes, reject NUL, and allow at most 4000 escaped UTF-8 bytes; RAW allows 2000 bytes. Non-null MySQL strings are rejected without trusted session collation; no collation is hardcoded. MySQL SQL must have identical placeholder positions under all supported SQL_MODE/ANSI_QUOTES quoting rules; executable comments and ambiguous syntax fail. Final SQL remains bounded by 64 MiB. Text results retain existing reader/metadata rules. Fallback values can appear in server SQL logs; driver logs still omit SQL/parameters. Real fallback syntax/version compatibility remains unverified.
- Oracle dictionaries use `GetComplexType(schemaName, typeName, transaction)`/`GetComplexTypeAsync` with exact dictionary names. Immutable `OceanBaseComplexType.Members` describes ordered attributes or a collection element; `CreateValue(...)` constructs `OceanBaseComplexValue` snapshots and `GetValues()` copies arrays/RAW bytes. Nested values must use the member's `ComplexType`. Supported members: NUMBER, VARCHAR2 (including VARCHAR)/CHAR, RAW, DATE, TIMESTAMP, and nesting thereof. Cycles and LOB/cursor/national members are unsupported.
- Named ARRAY/STRUCT result columns require preloading in the same connection/transaction and binary server-prepared results (call `Prepare()` for parameterless SQL) or REF CURSOR. For ordinary prepared queries whose type owner is omitted, an exact source table/column dictionary lookup runs on the same connection before execution. It uses the declared type owner or an unambiguous local type dependency, never a name-only cache match; missing or ambiguous identities fail. `GetValue`/`GetFieldValue<OceanBaseComplexValue>` retain the dictionary description and nested snapshots. ProviderType is `OceanBaseDbType.Array`/`Struct`; DataTypeName retains the type name. SequentialAccess materializes only the current complex field and keeps later large fields streaming; pagination checks schema/type/version. Text complex results, unloaded named types, and unknown anonymous layouts fail, including NULL metadata. Wire version alone does not prove dictionary freshness; explicitly refresh after external type DDL.
- Anonymous scalar collection binary results decode NUMBER, VARCHAR2/CHAR, RAW, DATE, and TIMESTAMP using element metadata without preloading. `Type.IsAnonymous=true`, TypeName is empty, and reader DataTypeName is `ARRAY`. Ordinary/sequential reads share budgets and page identity checks. Result descriptions/values are read-only: `CreateValue` and parameter/output binding reject them; incomplete anonymous complex layouts also fail.
- Anonymous collection input uses factories such as `connection.CreateArrayType("RAW", transaction)`, accepting case-insensitive NUMBER, VARCHAR2, CHAR, RAW, DATE, TIMESTAMP only. Another overload accepts a named `OceanBaseComplexType` preloaded in that session for object/collection elements, without dictionary lookup or alias inference. Use `CreateValue(...)`; NULL input requires explicit `ComplexType`. Both ordinary prepare and PrepareExecute accept input. Factory descriptions bind to connection, physical session, and transaction generation and become invalid after cache clear. Anonymous scalar collections support PrepareExecute Output/InputOutput/ReturnValue under the declaration/terminal-response rules below; complex-element collections accept Input only. Result-created anonymous descriptions stay read-only.
- Named complex parameters set `Value` to `OceanBaseComplexValue`; non-null Input/InputOutput can infer type. NULL/Output/ReturnValue require `OceanBaseParameter.ComplexType`, which also sets Array/Struct provider type. Setting DbType, a non-complex provider type, or `ResetDbType()` clears the declaration. Values must share the description; Size/Precision/Scale must be zero. Cross-connection, reopened-session, changed-transaction, or cleared-cache values fail before sending. Complex output requires PrepareExecute and exact metadata, including NULL/zero rows. Values publish atomically only after complete success; trailing ERR, cancellation, or early close preserves old values. Parameter-header version zero does not detect external DDL.
- Anonymous scalar collection output uses factory descriptions. Output/ReturnValue requires explicit ComplexType; InputOutput can infer it from a factory value. The six scalar types above are supported. Responses must be anonymous collections with matching layouts (NUMBER normalizes codes 0/3/246), including NULL/zero rows. Anonymous wire schema supplies no named identity. Output values retain the execution snapshot's factory description and remain reusable under session rules; later parameter-declaration changes do not affect in-flight types. Anonymous complex output remains rejected without full element identity; absent declarations/read-only result descriptions cannot bypass validation.
- Oracle array execution uses `((OceanBaseCommand)command).ExecuteArray(rowCount)`/`ExecuteArrayAsync(rowCount, token)` on all five assets, with PrepareExecute enabled and the current transaction explicitly bound. Rows range 1–65535. Every Input/InputOutput is a factory anonymous collection of that length; Output/ReturnValue declares a factory anonymous collection type. One request executes the parameter set without automatic commit/rollback/replay. INSERT/UPDATE/DELETE/MERGE, BEGIN/DECLARE/CALL, and StoredProcedure are supported; SELECT/DDL/FetchSize are rejected.
- Array `Items` use zero-based input positions and Succeeded/Failed/Unknown statuses, server codes, and per-item DML counts. PL/RETURNING's first column is a position, not a count, so per-item counts are null; complete RecordsAffected is the server aggregate. Row errors return Failed; trailing ERR/protocol/network errors still throw. `command.ArrayBindingResult` retains received partial results, marks unconfirmed suffixes Unknown, and is null before SQL is sent. Item success does not commit the caller's transaction.
- Array OUT/RETURNING supports the six scalars and preloaded named complex elements; each item can return multiple rows. `Items[i].OutputRows` follows SQL output-binding order. After complete response/OB20 validation, output Value becomes `object[][]` (input position, then returned rows; zero rows = empty array; NULL = DBNull). Failure preserves old Value. Reset InputOutput to a factory collection before another execution. Snapshots copy RAW; total output is limited to 65535 values/64 MiB raw field bytes. Server error text is not exposed. Basic array execution passed on the tested Oracle 4.4.2.2 tenant; additional output shapes and OBProxy remain outside that evidence.
- Dictionary lookup reserves the current physical session, requires the active transaction explicitly, and rejects active readers. Close/reopen, transaction changes, or `ClearComplexTypeCache(transaction)` invalidates all old descriptions/values, whose contents remain inspectable. Clear/reload after external DDL; cross-session DDL is not detected automatically. Type depth is at most 32; session caches allow 65535 members, 65535 named types, and 4 MiB dictionary UTF-8 text. Clear/reload when full. Each lookup uses connection CommandTimeout.
- `Use Oracle Prepare Execute=true` (builder `UseOraclePrepareExecute`, default false) enables Oracle StoredProcedure, function ReturnValue, and Text scalar OUT/InputOutput/RETURNING. First execution queries `ob_version()` and requires >=2.2.76. Procedure names must be qualified identifiers; values use binary bindings. Output follows result metadata, and internal output rows are hidden from readers. Values publish together after all results/boundaries succeed; failure/early close preserves old values. Zero output rows yield DBNull; multiple output rows, repeated OUT placeholders, independent Prepare on this path, and FetchSize are rejected. Scalar OUT/InputOutput, stored procedures, RETURNING, and streamed OUT passed on the tested Oracle 4.4.2.2 tenant; wider versions and OBProxy remain unverified.
- Oracle REF CURSOR output uses `OceanBaseDbType.RefCursor` (Output/ReturnValue only; Size/Precision/Scale zero) and PrepareExecute. Non-null output is `OceanBaseRefCursor`, read once using `GetDataReader()`/`GetDataReaderAsync()`. Default pages hold 128 rows; positive fetchSize and SequentialAccess/CloseConnection are supported. Handles bind to connection/transaction generation and cannot open after transaction end or close/reopen. Disposing the parent command does not close returned cursors. Multiple cursors can be read sequentially; one active reader per connection; output aliases of the same server ID share an object. Exhaustion reclaims the cursor. Dispose unread handles; early reader/cursor close destroys the session. Reexecution does not dispose old outputs for the caller. Input/InputOutput cursors and ordinary cursor result columns are unsupported. REF CURSOR output passed on the tested Oracle 4.4.2.2 tenant; broader interoperability remains open.
- `Use Lob Locators=true` (builder `UseLobLocators`, default false) requires PrepareExecute and negotiated locator capability. Oracle BLOB/CLOB columns and explicit Blob/Clob outputs return `OceanBaseLob`, never locator bytes as content. ByteLength is always bytes. BLOB uses `OpenRead()`; CLOB uses strict UTF-8 `OpenTextReader()`. Each handle opens once, after the original reader is exhausted. Chunk reads use the original session; active streams reserve it. Disposing a stream/handle permits connection reuse; read cancellation/timeout may destroy the session. Modern assets support async stream/handle disposal.
- LOB handles bind to connection, physical session, and transaction generation; close/reopen or transaction end invalidates them. Same-context handles support Input/InputOutput. Output/ReturnValue explicitly declares Blob/Clob and publishes atomically at the complete terminal response. BLOB chunks are at most 32767 bytes; CLOB chunks at most 8191 Unicode scalars. No whole-LOB buffering or separate connection is used.
- LOB updates use `WriteBytes(byteOffset, buffer, offset, count)`, `WriteText(characterOffset, text)`, `Truncate(length)`, and Async variants. Offsets start at zero: bytes for BLOB, Unicode scalars for CLOB; truncate uses the same units. Exhaust the original reader and dispose active streams first. A multi-chunk operation exclusively reserves the original session, transaction, and timeout without autocommit. Each confirmed chunk updates its locator. Operations are not atomic: failures can leave a successful prefix, never auto-rollback/replay, and require reacquiring the handle. Unconfirmed changes report unknown outcomes; cancellation/timeouts/protocol errors may destroy the session.
- `connection.CreateTemporaryLob(OceanBaseDbType.Blob/Clob, transaction)`/`CreateTemporaryLobAsync` creates SESSION-duration, cache=FALSE temporary LOBs using connection CommandTimeout; explicitly pass the active transaction. Creator handles call `FreeTemporary()`/`FreeTemporaryAsync()`; after successful or in-flight failed free, the source handle is unusable. Ordinary query/output handles have no free authority. Free before transaction end/Dispose and after closing streams. Dispose only cleans client resources/cancels in-flight operations; unfreed or failed-free objects can remain until original connection close. Failure after creation SQL begins sending (including trailing ERR), or cancellation/session change preventing safe handle return, destroys that original session to reclaim resources without affecting a reopened session. Trusted version-probe ERR/unsupported versions before creation SQL preserve the session. Temporary BLOB/CLOB create, mutation, read, and explicit free passed on the tested Oracle 4.4.2.2 tenant; broader resource-failure semantics and OBProxy remain unverified.
- `Use OB20=true` (builder `UseOb20`, default false) requests OB20 only when handshake connection attributes and server capability confirm it; otherwise standard packets remain. Streaming frames, CRC, command boundaries, and cursor paging are supported. Protocol errors destroy the connection without replay. Real server/OBProxy compatibility remains unverified.
- `Enable Full Link Trace=true` (builder `EnableFullLinkTrace`, default false) requires OB20 and confirmed tracing capability; otherwise ordinary OB20 continues. Legacy/new-extra formats follow server sampling/recording controls and correlate existing Activity trace IDs. Ambient/internal IDs can work without listeners. Only fixed module, IDs, and times are sent, never SQL, parameters, credentials, endpoints, arbitrary Activity tags, or baggage. Completed records accompany the next request; close does not flush a final record. Real sampling/SHOW TRACE acceptance remains open.
- GetSchema provides MetaDataCollections, DataSourceInformation, Tables, Columns, Procedures, ProcedureParameters, with true async APIs on modern assets. Routine collections include procedures/functions. Restrictions are catalog, schema, routine name, type or parameter name, package name; non-null values match exactly, with empty strings and `%`/`_` treated literally. Oracle package/overload/subprogram identity and original parameter type names are retained; unknown fields are DBNull. Return position is zero, direction RETURN. Catalog queries do not generate/bind parameters. The acceptance catalog cases passed on the tested 4.4.2.2 tenants; broader permission/version compatibility remains unverified. Oracle ChangeDatabase is unsupported.
- Batches execute sequentially without implicit transactions or whole-batch atomicity. Explicitly bind a local transaction when required.
- MySQL four-digit YEAR has local codecs/metadata/binding: ushort, zero or 1901–2155, explicit `OceanBaseDbType.Year`; no two-digit inference. Round trips passed on the tested MySQL-mode 4.4.2.2 tenant; other versions still require compatibility evidence.
- MySQL BIT(1–64) uses ulong, including BIT(1). Explicit `OceanBaseDbType.Bit` Size is bit width (zero means 64); out-of-width values fail before sending; Precision/Scale must be zero. Round trips passed on the tested MySQL-mode 4.4.2.2 tenant; the full version and edge-case matrix remains open.
- MySQL JSON supports local text/prepared reads/writes/metadata as strict UTF-8 strings, distinguishing JSON `null` from SQL NULL, including sequential GetTextReader. Explicit `OceanBaseDbType.Json` accepts string/NULL, Precision/Scale zero. The server validates syntax; objects are not implicitly serialized. Round trips passed on the tested MySQL-mode 4.4.2.2 tenant; the full version and edge-case matrix remains open.
- Oracle INTERVAL uses exact `OceanBaseIntervalYearToMonth`/`OceanBaseIntervalDayToSecond`, retaining sign, leading precision, and nanoseconds; standard/provider-specific access returns these structs. Explicit types or exact values with DbType.Object bind without Precision/Scale rounding. `ToTimeSpan()` succeeds only within range/tick precision; year-month intervals never become fixed durations. Round trips passed on the tested Oracle-mode 4.4.2.2 tenant; broader version coverage remains open.
- Oracle NCHAR/NVARCHAR2 has local text/prepared codecs and sequential character streams using independent session national UTF-8/UTF-16BE encoding. Trailing spaces are retained; unknown encodings fail. NCHAR/NVARCHAR2 round trips passed on the tested Oracle-mode 4.4.2.2 tenant; broader column/version compatibility remains open.

## Usage

Every asset supports the standard factory. This example creates objects without contacting a server:

```csharp
using OceanBaseConnector;

using var connection = OceanBaseProviderFactory.Instance.CreateConnection();
connection.ConnectionString = "Server=localhost;User ID=test_user;Password=replace-me;ExpectedMode=Oracle";
using var command = connection.CreateCommand();
command.CommandText = "select 1 from dual";
```

The optional DI package registers connections on all five targets:

```csharp
using Microsoft.Extensions.DependencyInjection;

services.AddOceanBaseConnection(connectionString);
```

Each OceanBaseConnection/DbConnection resolution creates a new closed connection with optional host logging, disposed by its resolving container scope. Registration/resolution does not connect. Existing DbConnection registrations from other providers are retained; prefer injecting the concrete type. Connections share no mutable state or implicit pool. Direct pre-open connection strings retain credentials by contract. Data-source registration does not register connections implicitly.

.NET 8/9/10 applications can share a data source:

```csharp
using OceanBaseConnector;

using var source = new OceanBaseDataSourceBuilder(connectionString).Build();
using var connection = source.CreateConnection();
// await connection.OpenAsync(cancellationToken);
```

With the optional DI package, `services.AddOceanBaseDataSource(connectionString)` registers OceanBaseDataSource and DbDataSource as the same singleton. `AddKeyedOceanBaseDataSource(key, connectionString)` registers independent keyed singletons. The container disposes data sources; callers dispose borrowed connections. Use builder UseLoggerFactory for host logging.

Default `TLS Mode=VerifyFull` validates system trust and hostnames; TLS failures never downgrade. Builder output and pre-open connection strings contain supplied credentials and require application protection. Data sources/open connections hide passwords by default; explicit `Persist Security Info=true` retains them. Driver logs/diagnostics omit SQL, parameter values, and credentials.

When `OceanBaseException.IsExecutionOutcomeUnknown=true`, sent SQL might have executed. The physical session is destroyed and SQL is never automatically replayed. Reconcile using business idempotency/transaction records rather than blindly retrying.

## Failures and unknown outcomes

Identify the failing phase before interpreting exceptions and business records. `IsExecutionOutcomeUnknown=false` means only that the driver did not mark an unknown outcome; it does not prove absence of side effects or authorize retry. State=Open alone does not prove reader exhaustion, transaction completion, or previous business success.

| Scenario | Driver behavior | Application action |
| --- | --- | --- |
| Parameter/option validation or a pre-cancelled execution token | Rejects entry; pre-cancellation sends no business SQL. | Correct inputs/cancellation; do not repeatedly retry validation errors as transient faults. |
| SQL might have been sent; disconnect, cancellation, or timeout without trusted completion | Throws OceanBaseException with unknown flag true and destroys the original session; InnerException retains interruption cause. | Record business identity/status and dispose the connection. Reconcile through a new connection; never directly replay writes, COMMIT, or a whole batch. |
| Trusted server ERR | Retains ServerErrorCode/SqlState, unknown=false. Ordinary non-cursor commands can finish/release the lease; cursor ERR destroys the session. | Follow error/transaction state; an error cannot prove earlier batch entries had no effects. |
| Closing an unconsumed reader | Destroys the physical session with its unfinished exchange; Close/Dispose can return normally while diagnostics report uncertainty. | Exhaust current and subsequent results to establish completion. Successful disposal does not prove SQL success or rollback. |
| Confirmed COMMIT/ROLLBACK followed by failed autocommit restoration | Returns the confirmed outcome, ends the transaction, destroys the session, and records TransactionRestoreAutocommitFailed. | Retain the confirmed outcome and reconnect; do not repeat committed work because cleanup failed. |
| Trusted COMMIT ERR | Retains an active transaction if the session remains Open for explicit rollback; destroyed sessions detach it. Untrusted responses mean unknown outcomes. | Explicitly roll back when usable; otherwise reconnect and reconcile. Do not blindly retry commit in the failed transaction. |

Disposing a field Stream/TextReader does not complete a command: exhaust or close its parent reader. Cancellation/timeout does not prove server KILL QUERY completion; interrupting local transport does not prove server execution stopped. Explicit Prepare failure may destroy a session without proving business Execute occurred. `Cancel()`, connection close, and timeouts never trigger automatic replay.

Batches run sequentially; stopping later entries does not undo the completed prefix. Modern DbException.BatchCommand identifies the original entry. Entry counts/RecordsAffected describe only known counts; queries/unexecuted entries may both be -1, so these cannot implement automatic resume. Bind an explicit local transaction for atomicity and account for unknown commit outcomes.

Multiple addresses are tried only after TCP connection failure within one total budget. TLS/authentication failure at the selected endpoint and failures after SQL sending never transparently switch endpoints. ExpectedMode cross-checks authenticated facts; it cannot force or guess a mode.

Troubleshooting can record driver version, target/runtime, sanitized endpoint/mode, exception type, codes/SQLSTATE, unknown flag, cancellation/timeout category, and business-operation ID. Do not report passwords, raw connection strings, SQL/parameters, or unsanitized captures. Log categories are OceanBaseConnector.Connection, .Command, .Transaction; endpoint/timing may appear, raw exception text does not. ActivitySource/Meter are named OceanBaseConnector, with `oceanbase.client.operations` and seconds-based `oceanbase.client.operation.duration`. Fixed tags contain operation, mode, outcome, and unknown flag only. Listener exceptions are isolated. First initialization failure can disable that channel for the assembly lifetime; missing spans do not prove SQL was not executed.

On the tested .NET 8.0.31 runtime, application MeterListeners without MeasurementsCompleted can retain subscriptions after disposal and affect later collection/disabled-listener costs. Set that callback (a no-op is sufficient without state) or explicitly DisableMeasurementEvents before disposal. The driver neither owns nor disposes application listeners.
