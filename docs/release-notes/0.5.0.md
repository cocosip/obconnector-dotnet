## OceanBaseConnector 0.5.0 — 2026-11-23

Both `OceanBaseConnector` and `OceanBaseConnector.DependencyInjection` use version 0.5.0.
The existing target frameworks remain `netstandard2.0`, `netstandard2.1`, `net8.0`,
`net9.0` and `net10.0`.

## Breaking changes and migration

- Replace the connection-string keyword `ExpectedMode` with `CompatibilityMode`.
  The old keyword is rejected; there is no alias.
- Replace `OceanBaseConnectionStringBuilder.ExpectedMode` with `CompatibilityMode`.
  The property now uses the non-nullable `OceanBaseCompatibilityMode` enum.
  Use `Auto` instead of assigning null or omit the connection-string option.
- The shared enum values are now `Auto = 0`, `MySql = 1`, `Oracle = 2`
  (previously `MySql = 0`, `Oracle = 1`). Recompile consumers and migrate any
  stored numeric enum values by their original meaning. These numbers are
  SDK values, not server protocol codes. Connection strings accept enum names only.
  Update or rebuild dependent providers and libraries as well: rebuilding only
  the application does not update enum constants compiled into its dependencies.

Before:

```text
Server=...;User ID=...;ExpectedMode=Oracle
```

After:

```text
Server=...;User ID=...;CompatibilityMode=Oracle
```

```csharp
var builder = new OceanBaseConnectionStringBuilder(connectionString)
{
    CompatibilityMode = OceanBaseCompatibilityMode.Auto
};
```

## Mode behavior

- Omitting `CompatibilityMode` and explicitly setting `CompatibilityMode=Auto`
  both detect and accept the authenticated MySQL or Oracle tenant mode.
- Explicit `MySql` or `Oracle` requires the actual mode to match; a mismatch
  fails Open. The option does not change the server's mode.
- The builder, connection and parameters share `OceanBaseCompatibilityMode`.
  An open connection reports concrete `MySql` or `Oracle`, never `Auto`;
  a closed connection reports null.
- `OceanBaseParameter.CompatibilityMode` retains its creation-time snapshot
  behavior. Execution uses the current session's actual mode. Parameters created
  directly or before Open report null. Use the open connection's mode when choosing SQL.
- Omitted and explicit Auto configurations share the same canonical pool identity;
  explicit mode requirements remain isolated.

## Validation scope

Before release preparation, all five target frameworks built without warnings or errors.
The local suite passed 10,335 unit tests and 133 consumer, dependency injection and
integration-configuration checks. Direct MySQL and Oracle database validation passed
230 cases, including the 28-case configuration/connection/parameter matrix and
202 connection-pool, command, parameter-derivation, type, metadata and transaction cases.
Four optional cases lacked alternate-database or specialized authentication/autocommit
connection configuration and were skipped; they are not counted as passing.

The 0.5.0 package verifier also passed for all five target assets, including
40 direct MySQL/Oracle live package scenarios covering sync/async operations,
buffered/sequential reads, transactions and cleanup.

These results retain the existing environment and capability boundaries documented in
[compatibility and known limitations](https://github.com/cocosip/obconnector-dotnet/blob/v0.5.0/docs/compatibility.md).
