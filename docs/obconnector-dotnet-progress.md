# SDK feature, capability, and support-boundary matrix

Updated: 2026-11-04. This document is the single entry point for the current feature scope.
[Scope decisions](obconnector-dotnet-missing-features-roadmap.md#scope-decisions) pin the official documentation and Java version and explain the O/J numbering;
the [gap matrix](obconnector-dotnet-completeness.md) lists development and acceptance gaps,
the [acceptance criteria](acceptance-criteria.md) define the completion conditions, and [compatibility](compatibility.md) keeps the environment blockers.

**This is currently an experimental driver; it does not promise full production-grade functionality.** "Implemented/partial" in the table below is source-code status,
and "direct subset" cites historical 4.4.2.2 records rather than a re-run or full-function acceptance. Any deployment support must be bound to
`server version + tenant mode + direct/ODP + protocol + TLS/auth + client OS/runtime + options`; "supports Oracle/MySQL" alone is not enough.

Scope: **core** means ADO.NET capabilities that must be correct; **optional** means explicit options/specific-mode extensions;
**candidate** means an extension with a .NET use case and grounds in a database/protocol or ADO.NET contract, but not part of the current promise; **excluded** items are not pending work.
"—" means the mode does not apply to that particular interface, not that the server lacks a similar SQL capability.

JDBC-exclusive interfaces, JVM integration, and behavior-compatibility configuration are not part of this matrix or the missing-feature count; see the
[scope decision table](obconnector-dotnet-missing-features-roadmap.md#jdbc-exclusive-interfaces-stay-out-of-the-net-matrix) for details.
Java classes/methods are implementation references only; corresponding ADO.NET behavior is judged by its own contract and cannot be ported item by item by name.

## How to read completion status

Source-code implementation closes only "missing implementation"; it cannot close the corresponding real TLS/ODP/version/platform gates.
The same capability must be confirmed separately for input, output, text, server prepare, fallback, multi-statement, stream/locator, and sync/async.
Exact failures, skips, not-yet-implemented items, and exclusions are maintained only in the [missing matrix](obconnector-dotnet-completeness.md);
the old 23-item checklist is no longer used to compute percentages. Historical summaries live in [real compatibility](compatibility.md).
